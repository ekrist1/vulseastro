# Admin Status View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show in the Vulse admin whether it is running against the local dev SQLite database or a remote production D1, plus bindings, version, and config warnings.

**Architecture:** A server-only helper (`getVulseStatus`) computes a `VulseStatus` object from the worker `env` and build mode during the existing SSR pass. `AdminShell.astro` computes it once, passes a compact slice to `SideNav.vue` (an always-visible badge under the logo), and a new admin page `settings/status.astro` renders the full detail. No new client API endpoint.

**Tech Stack:** TypeScript, Astro (SSR `.astro` pages), Vue 3 (`<script setup>`), Tailwind utility classes, Vitest for unit tests, Cloudflare Workers runtime (`cloudflare:workers` env, D1/R2/Queue bindings).

## Context the engineer needs

- **Spec:** `docs/superpowers/specs/2026-05-26-admin-status-view-design.md`.
- **`RuntimeEnv`** is defined in `packages/vulse/src/server/env.ts` (interface with `DB`, `BUCKET?`, `FORM_QUEUE?`, `BETTER_AUTH_SECRET`, `VULSE_PREVIEW_SECRET?`, `VULSE_ALLOW_MEMBER_SIGNUP?`, `CF_IMAGES_ACCOUNT_HASH?`, `CF_IMAGES_TOKEN?`, …).
- **Version constant:** `VULSE_VERSION` is exported from `packages/vulse/src/version.ts` (and re-exported from `src/index.ts`). It is generated by `scripts/sync-version.mjs` (runs on `pretest`/`build`).
- **Build mode:** `import.meta.env.DEV` is `true` under `astro dev` (local Miniflare SQLite) and `false` in a built/deployed worker (remote D1). This is the only available local-vs-remote signal — there is no D1 API for it.
- **Tests:** run with `pnpm test` (vitest) from `packages/vulse`. Unit tests live in `packages/vulse/tests/unit/*.test.ts`. Under vitest, `import.meta.env.DEV` is truthy, so the status module takes `isDev` as an explicit (defaulted) argument to stay testable.
- **Admin pages:** `.astro` files under `src/admin/pages`. They wrap content in `AdminShell` and pass an `activePath`. The Settings nav group currently links to `Site` (`/admin/settings`) and `Auth` (`/admin/settings/auth`), gated by `isAdmin`. Settings pages (e.g. `settings/auth.astro`) are **not** guarded inline — gating is by nav visibility only. Match that convention.
- **The placeholder auth secret** value to detect is exactly `dev-secret-change-me-in-production-32chars` (see `src/cli/setup.ts` `PLACEHOLDER_AUTH_SECRET`).

- [ ] **Step 3: Write the module**

Create `packages/vulse/src/server/status.ts`:

```ts
import type { RuntimeEnv } from './env.js'
import { VULSE_VERSION } from '../version.js'

/** The exact placeholder written by `vulse setup` when no secret is provided. */
const PLACEHOLDER_AUTH_SECRET = 'dev-secret-change-me-in-production-32chars'

export interface VulseStatus {
  mode: 'development' | 'production'
  database: 'local SQLite' | 'remote D1'
  version: string
  bindings: { db: boolean; bucket: boolean; queue: boolean; images: boolean }
  warnings: string[]
}

/**
 * Compute a snapshot of the running Vulse environment for the admin Status view.
 * Pure and side-effect-free; never throws.
 *
 * `isDev` defaults to `import.meta.env.DEV` (true under `astro dev` → local Miniflare
 * SQLite; false in a built/deployed worker → remote D1). It is a parameter so unit
 * tests can exercise both modes — under vitest `import.meta.env.DEV` is always truthy.
 */
export function getVulseStatus(env: RuntimeEnv, isDev: boolean = import.meta.env.DEV): VulseStatus {
  const mode = isDev ? 'development' : 'production'
  const warnings: string[] = []

  if (env.BETTER_AUTH_SECRET === PLACEHOLDER_AUTH_SECRET) {
    warnings.push('BETTER_AUTH_SECRET is still the placeholder value — set a strong secret before going to production.')
  }
  if (mode === 'production' && env.VULSE_ALLOW_MEMBER_SIGNUP === 'true') {
    warnings.push('Public member sign-up is enabled in production (VULSE_ALLOW_MEMBER_SIGNUP="true").')
  }

  return {
    mode,
    database: isDev ? 'local SQLite' : 'remote D1',
    version: VULSE_VERSION,
    bindings: {
      db: !!env.DB,
      bucket: !!env.BUCKET,
      queue: !!env.FORM_QUEUE,
      images: !!(env.CF_IMAGES_ACCOUNT_HASH && env.CF_IMAGES_TOKEN),
    },
    warnings,
  }
}
```
