# Getting started with Vulse

## Prerequisites

- Node 22+
- pnpm 9+
- A Cloudflare account (free tier is fine)
- `wrangler` CLI logged in (`wrangler login`)

## 1. Add Vulse to an Astro project

```bash
pnpm create astro@latest my-site
cd my-site
pnpm astro add vulse
pnpm astro add cloudflare
```

`astro add vulse` patches your `wrangler.toml`, scaffolds `src/vulse/collections/`, and prints the one-time setup commands.

## 2. Create D1 and R2

```bash
wrangler d1 create vulse-db
wrangler r2 bucket create vulse-media
```

Paste the returned `database_id` into `wrangler.toml` at the marked `TODO_PASTE_ID` location.

## 3. Migrate and seed

```bash
npx vulse migrate
npx vulse seed:admin --email you@example.com
```

The seed command prints a temporary password. You'll be prompted to change it on first login.

## 4. Run

```bash
pnpm dev
```

Open `http://localhost:4321/admin` and sign in.

## 5. Define your first blueprint

`src/vulse/collections/post.ts`:

```ts
import { defineCollection, z, blocks, media } from 'vulse'

export default defineCollection({
  name: 'post', label: 'Blog post',
  schema: z.object({
    title: z.string().min(1),
    slug: z.string(),
    excerpt: z.string().optional(),
    cover: media().optional(),
    body: blocks(),
    publishedAt: z.date().optional(),
  }),
  admin: { titleField: 'title', listColumns: ['title', 'publishedAt'] },
  access: {
    read: ({ user, entry }) => entry?.status === 'published' || !!user,
    create: ({ user }) => user?.role === 'admin' || user?.role === 'editor',
    update: ({ user, entry }) => user?.role === 'admin' || entry?.createdBy === user?.id,
    delete: ({ user }) => user?.role === 'admin',
  },
})
```

Reload `/admin` — the new collection appears in the sidebar.

## 6. Render content on your site

`src/content/config.ts` (generated by `astro add vulse`):

```ts
import { defineCollection } from 'astro:content'
import { vulseLoader } from 'vulse/loader'

export const collections = {
  post: defineCollection({ loader: vulseLoader({ collection: 'post' }) }),
}
```

`src/pages/blog/[slug].astro`:

```astro
---
import { getCollection } from 'astro:content'
import { BlockRenderer } from 'vulse/client'

export async function getStaticPaths() {
  const posts = await getCollection('post')
  return posts.map((p) => ({ params: { slug: p.data.slug }, props: { post: p } }))
}
const { post } = Astro.props
---
<article>
  <h1>{post.data.title}</h1>
  <BlockRenderer blocks={post.data.body} />
</article>
```

````markdown
# Deploying Vulse to Cloudflare

Vulse is built for Cloudflare Pages + Workers. One deploy hosts your public site, the admin UI, and the API.

## 1. Production database

```bash
# Apply Vulse + your migrations to the remote D1
npx vulse migrate --remote

# Seed the production admin user
npx vulse seed:admin --remote --email you@example.com
```

## 2. Secrets

Set the secrets Vulse requires:

```bash
wrangler secret put BETTER_AUTH_SECRET
wrangler secret put VULSE_PREVIEW_SECRET
# Only if you want CF Images variants:
wrangler secret put CF_IMAGES_ACCOUNT_HASH
wrangler secret put CF_IMAGES_TOKEN
```

If `CF_IMAGES_*` are unset, Vulse soft-degrades to serving raw R2 objects.

## 3. Deploy

```bash
pnpm build
wrangler pages deploy ./dist
```

Or use a connected Git deploy (Cloudflare Pages → connect your repo, set build command to `pnpm build`, output `dist/`).

## 4. Optional: cron purge for soft-deleted media

In `wrangler.toml`:

```toml
[triggers]
crons = ["0 3 * * *"]
```

And expose the scheduled handler — see [the cron handler reference](./reference/cron.md).

## 5. Promoting users

Sign-ups default to `member`. To promote someone, sign in as an admin and open `/admin/users`.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `D1 binding "DB" is missing` at runtime | Paste the D1 ID into `wrangler.toml` and redeploy. |
| 500 with `INTERNAL` code | Check Cloudflare logs. Most often: missing `BETTER_AUTH_SECRET`. |
| Images return 404 | Either `CF_IMAGES_ACCOUNT_HASH` is wrong, or no variants are registered. Run `npx vulse migrate` again (registration is idempotent). |
| Public page shows old content | Pages caches; trigger a rebuild via the deploy hook in `/admin/settings`. |
````
