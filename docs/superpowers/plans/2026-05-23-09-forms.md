# Plan 9 — Forms Builder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a first-party form builder: admin defines forms (field list + validation + emails), public site embeds headless `FormRenderer`, submissions persist in D1, admin notify + optional confirmation emails send asynchronously via `FORM_QUEUE`, file uploads use draft TTL purge, developers hook via integration config.

**Architecture:** Separate forms domain (`vulse_forms`, `vulse_form_submissions`) — not collections. `FormEditor.vue` forks blueprint editor UX. Submit handler validates synchronously, enqueues `FormProcessJob`, returns immediately. Queue consumer runs notify/confirmation/webhooks + `onSubmit` / `onAfterProcess` hooks.

**Tech Stack:** Zod compile (reuse blueprint patterns), R2/media for files, Cloudflare Queues (`FORM_QUEUE`), Email Workers (with graceful degrade), D1 rate-limit table.

**Spec reference:** [2026-05-23-forms-design.md](../specs/2026-05-23-forms-design.md) — full data model, API, spam, hooks.

**Prerequisites:** Plans 1–7 complete (media/R2, admin shell, settings, auth). Plan 8 (E2E) can add a form journey after Plan 9 lands.

**Locked decisions:**
- Dedicated `FORM_QUEUE` binding
- Skip confirmation when `toField` empty/missing; always notify admin when configured
- Infinite storage; manual delete in admin (+ API)

### Task 7: FORM_QUEUE + async processing

**Files:**
- Create: `packages/vulse/src/server/forms/queue.ts`
- Create: `packages/vulse/src/server/forms/process-submission.ts`
- Create: `packages/vulse/src/server/forms/templates.ts`

- Modify: `playground/vulse-play/wrangler.toml` (document `[[queues.producers]]` / `consumers`)
- Create: `packages/vulse/tests/integration/form-process.test.ts`

- [ ] **Step 1: Queue binding**

Message shape: `{ type: 'process_submission', submissionId: string }`.

Producer: `env.FORM_QUEUE.send(...)` after successful submit.

Consumer: `export async function vulseFormQueue(batch, env)` — process each message.

Document in README + playground `wrangler.toml`:

```toml
[[queues.producers]]
queue = "vulse-form-queue"
binding = "FORM_QUEUE"

[[queues.consumers]]
queue = "vulse-form-queue"
max_batch_size = 10
max_batch_timeout = 30
```

- [ ] **Step 2: Template renderer**

`renderTemplate(template, { form, submission, payload })` — mustache-lite `{{field}}` tokens.

- [ ] **Step 3: Email sender**

`sendFormEmail(env, { to, subject, body })` — Email Workers when configured; else throw `email_not_configured` (submission stays stored, status `failed`).

- [ ] **Step 4: Process pipeline**

1. Load submission + form
2. **Notify** — always run if `settings.notifyEmails.length > 0`
3. **Confirmation** — only if `confirmationEmail.enabled` AND `toField` set AND payload[toField] non-empty
4. **Webhooks** — from `actions`
5. Integration hooks (`onSubmit`, `onAfterProcess`) from stored integration config
6. Set `status = processed` or `failed` + `error`

- [ ] **Step 5: Wire submit handler**

Replace enqueue stub with real `FORM_QUEUE.send`.

- [ ] **Step 6: Tests**

Mock email sender; assert notify always sent; confirmation skipped when email field empty; webhook called; status updated.

- [ ] **Step 7: Commit**

```bash
git commit -m "feat(vulse): FORM_QUEUE async submission processing"
```
